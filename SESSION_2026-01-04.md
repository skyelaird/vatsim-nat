## Critical Bug Fix: Collector Entry Detection

### Problem Identified
The collector was marking flights as "entered" immediately when first detected in the broad NAT region (-60W to -10W), causing:
- Westbound flights marked "entered" at -10W (outside actual -15W boundary)
- Eastbound flights marked at wrong positions
- Dashboard showing zero approaching flights (all marked as already entered)
- UAL42, HGO46A, BAW99S, GEC8320 all incorrectly marked

### Root Cause
1. `NAT_LON_EAST` boundary set to -10W instead of actual -15W NAT boundary
2. `create_crossing()` set `entry_time` immediately on first detection
3. No logic to detect actual boundary crossing

### Fix Implementation (collector_service.py)

**Changes:**
1. Updated `NAT_LON_EAST` from -10W to -15W (actual NAT boundary)
2. Updated `EXIT_ZONE_EAST` from -10W to -15W for consistency
3. Modified `create_crossing()` to set `entry_time=NULL` initially (flight monitored but not entered)
4. Added `has_entered_nat()` function to detect actual boundary crossings:
   - Eastbound: crosses from -45W eastward to -45W westward
   - Westbound: crosses from west of -15W to -15W or eastward
5. Added `update_entry()` function to set entry_time when boundary actually crossed
6. Updated `process_flight()` to check for entry crossing on each position update
7. Updated `get_active_crossing()` to handle NULL entry_time properly
